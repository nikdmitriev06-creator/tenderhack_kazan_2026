# Сценарии показа

Стенд: `docker compose up -d --build`, затем `docker compose exec api python -m app.tools.evaluate`.
Все сценарии проходят автоматически: `frontend/e2e/flows.js` (playwright-cli, раздел «Разработка» в README).
Примеры подобраны под демо-справочник; на справочнике организаторов их нужно сверить.

## 1. Неоднозначный КТРУ → вопрос → код (Т2.4, Т2.5)

1. «Создание СТЕ» → пример «Неоднозначный КТРУ» («Бумага офисная А4 500 листов»), «Заполнить по описанию».
2. Подходят три позиции; модуль спрашивает «Цветность» и показывает, сколько отсечёт каждый вариант. Последний
   вариант — «Ничего не подходит»: честный отказ вместо выбора наугад.
3. Ответ «Белая» → итоговый код 17.12.14.129-00000031.
4. В листе товара маркером отмечены фрагменты, из которых взяты значения; «80» приведено к корзине «≥80 … <90».

## 2. Недопустимое значение (Т3)

1. Пример «Недопустимое значение»: «Интенсивность цвета: Белый» — так ошибаются настоящие поставщики (карточка
   портала 47453345 и фильтры каталога).
2. Замечание: значения нет в перечне позиции, с перечнем допустимых и правилом модерации.
3. Второе замечание: «500л» в наименовании, с готовым исправлением наименования.

## 3. Опечатка (Т3)

Пример «С опечаткой»: «Медимум» → «Медиум», зачёркнуто красным карандашом, значение из перечня.

## 4. Проверка и модерация

1. «Принять всё», «Проверить перед отправкой», «Отправить на модерацию». В карточку идут только принятые строки:
   ответ на вопрос решения по строкам не сбрасывает. Пустая обязательная характеристика — блокирующее замечание.
2. «Заявки»: модератор видит карточку и замечания модуля; текст возврата уже собран из блокирующих замечаний.

## 5. Массовая загрузка (Т6)

Файл `backend/tests/fixtures/fake/ste.xlsx` (15 строк): прогресс, статус каждой строки, «Открыть в форме»,
файл с результатом. Строка вне справочника получает статус «нет в справочнике» с причиной в «Замечаниях».

## 6. Метрики (Т5) и API

«Метрики»: точность кода, заполнение, детектор по видам ошибок, честный отказ вне справочника, задержки, порог —
у каждой цифры выборка и способ расчёта. «API»: поток, методы, настоящие примеры запроса и ответа, Swagger, BPMN.

Ниже — живые карточки Портала поставщиков (8 520 СТЕ, публичный API): доля карточек, нарушающих правила
модерации, с примером-ссылкой на каждое правило; ошибки ввода, которые нашёл модуль («900 мл» в наименовании и
«900 л» в характеристике, «9 В» и «-30 В»), каждая открывается на портале; заполнение против введённого
поставщиком. Отчёт собирает `app.tools.portal_report`, данные лежат в `data/portal/` (вне git).

## 7. Вне справочника

«Услуги по уборке помещений» → «Категория не найдена в справочнике», ни одной подставленной позиции.

Товар рядом со справочником: «Батарейка AA щелочная 1,5 В» — в наименовании есть слова, которых нет у позиции
(«батарейка»: в справочнике позиция названа иначе), поэтому модуль просит «Подтвердите позицию КТРУ» с названием позиции и вариантом «Ничего не
подходит». Итоговый код — только после подтверждения.
